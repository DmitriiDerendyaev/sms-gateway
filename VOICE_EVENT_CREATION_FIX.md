# Исправление обработки голосовых сообщений для создания событий

## Проблема

В логах наблюдались следующие проблемы с голосовыми сообщениями в режиме создания событий:

1. **Неправильный системный промпт**: GigaChat получал общий промпт "Внимательно слушай..." вместо специализированного для создания событий
2. **Двойное списание токенов**: Сначала за транскрибирование, потом за парсинг текста в JSON
3. **Неправильная обработка ответа**: GigaChat возвращал общий ответ вместо чистого текста описания события

## Решение

### 1. Специальный промпт для голосовых сообщений в режиме создания событий с передачей текущего времени

```java
// Получаем текущее время для промпта
ZonedDateTime nowUtc = ZonedDateTime.now(ZoneId.of("UTC"));
String currentDateTime = nowUtc.format(DateTimeFormatter.ISO_INSTANT);
String currentDate = nowUtc.format(DateTimeFormatter.ofPattern("yyyy-MM-dd"));
String currentTime = nowUtc.format(DateTimeFormatter.ofPattern("HH:mm"));

if (STATE_CREATING_EVENT.equals(state)) {
    // Специальный промпт для создания событий календаря с текущим временем
    audioSystemPrompt = "Ты - помощник для создания событий в Google Calendar. " +
            "Пользователь отправил голосовое сообщение с описанием события. " +
            "КРИТИЧЕСКИ ВАЖНО - ТЕКУЩЕЕ ВРЕМЯ:\n" +
            "Сейчас: " + currentDateTime + "\n" +
            "Сегодня: " + currentDate + ", время: " + currentTime + " UTC\n\n" +
            "Твоя задача - РАСПОЗНАТЬ текст и вернуть ТОЛЬКО описание события...";
} else {
    // Обычный промпт для общего общения
    audioSystemPrompt = "Внимательно слушай, анализируй ситуацию...";
}
```

### 1.1. Передача текущего времени в промпт

**Проблема:** GigaChat не знал текущее время, поэтому неправильно интерпретировал относительное время ("через 1 час", "завтра").

**Решение:** Передаем текущее время UTC в системный промпт:
```
КРИТИЧЕСКИ ВАЖНО - ТЕКУЩЕЕ ВРЕМЯ:
Сейчас: 2024-12-14T15:30:00Z
Сегодня: 2024-12-14, время: 15:30 UTC
```

**Результат:** GigaChat теперь правильно понимает контекст времени для создания событий.

### 2. Единая обработка токенов

**До исправления:**
- Транскрибирование: списание токенов ✅
- Парсинг в JSON: списание токенов ✅
- **Результат:** Двойное списание

**После исправления:**
- Транскрибирование: списание токенов, потом возврат баланса ↩️
- Парсинг в JSON: списание токенов ✅
- **Результат:** Корректное однократное списание

### 3. Правильная последовательность обработки

1. **Пользователь в состоянии CREATING_EVENT отправляет голосовое сообщение**
2. **Загрузка файла в GigaChat** (без списания токенов)
3. **Транскрибирование с правильным промптом**
4. **Возврат токенов** (промежуточный шаг)
5. **Передача текста в handleEventCreation**
6. **Парсинг текста в JSON через EventParserService**
7. **Создание события в Google Calendar**
8. **Финальное списание токенов**
