# Реализация поддержки часовых поясов для создания напоминаний

## Обзор изменений

Добавлена полная поддержка часовых поясов для корректного создания напоминаний в разных временных зонах. Система теперь учитывает локальное время пользователя при интерпретации текстовых и голосовых сообщений.

## Архитектурные изменения

### 1. База данных

**Файл:** `src/main/resources/db/migration/V4__add_timezone_to_users_table.sql`

Добавлены новые поля в таблицу `users`:
- `timezone_offset` (INTEGER) - смещение от UTC в часах (-12 до +14)
- `timezone_set_at` (TIMESTAMP) - дата установки часового пояса

```sql
ALTER TABLE users
ADD COLUMN IF NOT EXISTS timezone_offset INTEGER,
ADD COLUMN IF NOT EXISTS timezone_set_at TIMESTAMP;
```

### 2. Модель данных

**Файл:** `src/main/java/ru/derendyaev/SmsGatewayLLM/model/UserEntity.java`

Добавлены поля для хранения информации о часовом поясе:
```java
@Column(name = "timezone_offset")
private Integer timezoneOffset;

@Column(name = "timezone_set_at")
private LocalDateTime timezoneSetAt;
```

### 3. Сервис пользователей

**Файл:** `src/main/java/ru/derendyaev/SmsGatewayLLM/service/UserService.java`

Добавлены методы для работы с часовыми поясами:

- `hasTimezone(UserEntity user)` - проверка установлен ли timezone
- `setTimezone(UserEntity user, Integer timezoneOffset)` - установка timezone
- `getTimezoneOffset(UserEntity user)` - получение смещения
- `parseTimezoneOffset(String timezoneStr)` - парсинг строки с timezone

### 4. Парсер событий

**Файл:** `src/main/java/ru/derendyaev/SmsGatewayLLM/service/EventParserService.java`

Обновлен метод `parseTextToEventJson` для поддержки timezone:

```java
public String parseTextToEventJson(String userText, Integer timezoneOffset)
```

- При наличии timezoneOffset рассчитывается локальное время пользователя
- Промпт для GigaChat содержит локальное время пользователя
- Сохранена обратная совместимость через перегрузку метода

### 5. VK контроллер

**Файл:** `src/main/java/ru/derendyaev/SmsGatewayLLM/vk/VkWebhookController.java`

#### Новые состояния:
- `STATE_WAITING_TIMEZONE` - ожидание выбора часового пояса

#### Новые константы кнопок:
- `BUTTON_TIMEZONE_PLUS_2`, `BUTTON_TIMEZONE_PLUS_3`, `BUTTON_TIMEZONE_PLUS_4`

#### Новые методы:
- `requestTimezoneSelection(Integer userId)` - запрос выбора timezone
- `handleTimezoneSelection(Integer userId, String buttonPayload)` - обработка выбора кнопками
- `handleManualTimezoneInput(Integer userId, String timezoneText)` - обработка ручного ввода
- `proceedToEventCreation(Integer userId)` - продолжение создания события
- `createTimezoneKeyboardJson()` - клавиатура выбора timezone

#### Измененная логика:
1. При нажатии "Создать напоминание" проверяется наличие timezone
2. Если timezone не установлен - показывается выбор timezone
3. После установки timezone - продолжается обычный процесс создания события
4. Все промпты (текстовые и голосовые) используют локальное время пользователя

## Технические детали

### Расчет локального времени

```java
// UTC время
ZonedDateTime nowUtc = ZonedDateTime.now(ZoneId.of("UTC"));

// Локальное время пользователя
ZonedDateTime userLocalTime = (timezoneOffset != null) ?
        nowUtc.plusHours(timezoneOffset) : nowUtc;
```

### Формат промпта для GigaChat

```
КРИТИЧЕСКИ ВАЖНО - ТЕКУЩЕЕ ВРЕМЯ (локальное время пользователя UTC+3):
Сейчас: 2024-12-14T18:30:00Z
Сегодня: 2024-12-14, время: 18:30 UTC+3
```

### Обработка относительного времени

- "через 1 час" → рассчитывается от локального времени пользователя
- "завтра в 10:00" → 10:00 в локальном времени пользователя
- Все абсолютные времена интерпретируются в локальном контексте

## Обратная совместимость

- Пользователи без установленного timezone продолжают работать в UTC
- Существующие методы сохраняют работоспособность
- Миграция добавляет поля без нарушения существующих данных

## Валидация и ограничения

### Диапазон timezone_offset:
- Минимальное значение: -12 часов
- Максимальное значение: +14 часов

### Форматы ввода timezone:
- `+2`, `+3`, `-5`, `+4`
- Регистр не важен
- Дробные значения не поддерживаются

### Обработка ошибок:
- Некорректный формат → сообщение об ошибке + повторный запрос
- Выход за диапазон → исключение IllegalArgumentException
- Null значения → fallback на UTC
